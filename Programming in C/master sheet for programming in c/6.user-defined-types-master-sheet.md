### 2. COMPLETE COMPRESSED MODULES (Chunked + Active Recall)

#### M1. Structures (`struct`): Access, Precedence & Passing

* **Cue:** How do `.` and `->` interact with `*` and `++`, and when should you pass a `struct` by value vs pointer?
* **Intuition (Feynman):** A `struct` glues multiple variables into one contiguous box; `.` opens a box directly, while `->` follows an address to the box first.
* **Mechanics:**
* **Member Access:** `s.x` accesses via object; `p->x` is strictly equivalent to `(*p).x` (access via pointer).
* **Precedence Hierarchy:** Postfix (`.`, `->`, `x++`) beats Prefix/Dereference (`*x`, `++x`). Parse `*p->x` as `*(p->x)`, `++p->x` as `++(p->x)`, `*p++` as `*(p++)`, and `(*p)++` as increment target value.
* **Operations & Passing:** Direct copy `s1 = s2` is **valid** (shallow byte copy); `s1 == s2` is a **compile error** (padding holds garbage). Pass by value copies `sizeof(struct)` bytes (`O(size)`); pass `const struct S *` copies only `4B`/`8B` (`O(1)`).


* **Example:** Given `struct Node { int *val; } *p;`, `*p->val++` parses as `*((p->val)++)` (reads `*val`, advances pointer `val`), whereas `(*p->val)++` increments the integer itself.
* **Trap / Edge Case:** Comparing two structs with `memcmp(&s1, &s2, sizeof(s1))` can return false for equal fields because uninitialized **padding bytes** contain random stack garbage.

#### M2. Memory Alignment & Structure Padding

* **Cue:** How do you compute `sizeof(struct)` by hand, and how does field ordering shrink memory footprint?
* **Intuition (Feynman):** CPUs fetch data fastest at addresses divisible by the data's width, so the compiler inserts invisible spacer bytes (padding) inside and at the end of structs.
* **Mechanics:**
* **Rule 1 (Member Offset):** Every member of alignment `A` (usually `sizeof(scalar)`, or `max_align` for nested structs; arrays use their **element's** alignment) must start at an offset where `offset % A == 0`.
* **Rule 2 (Trailing Padding):** Total `sizeof(struct)` must be a multiple of the struct's **largest member alignment (`max_A`)** so elements of `struct S arr[N]` stay aligned.
* **Padding Minimization:** Ordering fields from **largest alignment to smallest** (e.g., `double` → `int` → `short` → `char`) packs gaps tightly and minimizes total size.


* **Example:** (1B `char`, 4B `int`): `struct A { char x; int y; char z; };` → `x@0`, 3B pad, `y@4..7`, `z@8`, 3B tail pad = **`12B`**. Reordered `{ int y; char x; char z; }` → `y@0..3`, `x@4`, `z@5`, 2B tail pad = **`8B`**.
* **Trap / Edge Case:** An array field like `char buf[10]` has alignment `1` (from `char`), **not** `10`; also, taking the address `&s.bf` of a **bit-field** (`unsigned x : 3;`) is a compile-time error.

#### M3. Self-Referential Structures (DS & OS Backbone)

* **Cue:** Why can a `struct` hold a pointer to itself but never an instance of itself, and how does this wire C data structures?
* **Intuition (Feynman):** A box cannot physically contain a full copy of itself (infinite size), but it can easily hold a tiny slip of paper with the next box's address.
* **Mechanics:**
* **Size Constraint:** `struct Node next;` inside `struct Node` → **compile error** (incomplete type / infinite recursion); `struct Node *next;` → **valid** (pointer size is fixed `4B`/`8B`).
* **Core DS Layouts:** Singly LL (`int data; struct Node *next;`) | Doubly LL (`prev`, `next`) | Binary Tree (`left`, `right`) | Graph Adjacency List (`struct Edge *adj[V]` array of list heads).
* **Struct Tag Rule:** Inside a `typedef struct`, the alias name does not exist until after `}` → always name the struct tag so internal self-pointers compile.


* **Example:** `typedef struct Node { int data; struct Node *left, *right; } Node;` builds a clean binary tree node usable as `Node *root;`.
* **Trap / Edge Case:** Writing `typedef struct { int x; Node *next; } Node;` fails to compile because `Node` is undeclared inside the braces—always write `struct Tag *next;`.

#### M4. Unions (`union`) & Endianness Inspection

* **Cue:** How is `sizeof(union)` calculated, and how does a union expose CPU byte ordering (endianness)?
* **Intuition (Feynman):** A `union` is a single shared studio room where all members start at byte 0 and overwrite each other—only one tenant lives there at a time.
* **Mechanics:**
* **Memory Sharing:** All members share offset `0`; writing `u.b` overwrites `u.a`'s raw bytes. Ideal for saving RAM in **tagged unions** (`struct` holding an `enum` type-tag + `union` payload).
* **Exact Size Formula:** `sizeof(union) = smallest multiple of (max member alignment) that is at least (max member size)`.
* **Endianness Probe:** Overlap `unsigned int x = 0x01020304;` with `unsigned char b[4];` → **Little-Endian** (x86/ARM) stores LSB `0x04` at lowest address `b[0]`; **Big-Endian** (Network) stores MSB `0x01` at `b[0]`.


* **Example:** `union U { int a; char b[5]; };` (4B `int`) → max size is `5`, max alignment is `4` → padded up to **`8B`** (not `5B`).
* **Trap / Edge Case:** Initializing multiple union members simultaneously (`union U u = {1, 2};`) is a compile error; C initializes only the **first** member (or one designated member like `{ .b = 'A' }`).

#### M5. `enum` & `typedef`

* **Cue:** How do `enum` constants auto-number, and why is `typedef` strictly superior to `#define` for pointer types?
* **Intuition (Feynman):** `enum` replaces magic numbers with readable integer labels, while `typedef` registers true type nicknames inside the compiler instead of doing blind find-and-replace.
* **Mechanics:**
* **`enum` Numbering:** First unassigned constant = `0`; every subsequent unassigned constant = `previous + 1`. Duplicate values and explicit jumps are legal (`{ A, B = 5, C, D = 2, E }` → `0, 5, 6, 2, 3`).
* **`enum` Constraints:** Enumerators are compile-time `int` **R-values** (cannot do `A++` or `&A`), and share the enclosing scope (two enums in the same scope cannot reuse the same constant name).
* **`typedef` Mechanics:** Processed by the **compiler** (respects scope, binds pointers tightly) vs `#define` (blind preprocessor text substitution). Simplifies function pointers (`typedef int (*Cmp)(int, int);`).


* **Example:** `typedef int* IntPtr; IntPtr p, q;` declares **both** `p` and `q` as `int *`; `#define IntPtr int*` followed by `IntPtr p, q;` expands to `int* p, q;` where `q` is a plain `int`.
* **Trap / Edge Case:** Applying `const` to a pointer `typedef` (`typedef int* P; const P x;`) makes `x` a **constant pointer** (`int *const x`), **not** a pointer to `const int` (`const int *x`)!

### 3. CONFUSION-KILLER TABLE (Interleaving)

| Concept | Core Difference | When to Use / Trigger | Common Trap |
| --- | --- | --- | --- |
| **`struct` vs `union**` | `struct` gives each member separate offsets (sum + pad); `union` overlays all at offset `0` (max + align). | Grouping simultaneous fields vs mutually exclusive variants / byte inspection. | Thinking `sizeof(union)` is strictly `max(sizeof(m))` without alignment rounding. |
| **`*p->x` vs `(*p)->x**` | `*p->x` = `*(p->x)` (deref pointer member `x`); `(*p)->x` = `(**p).x` (when `p` is `struct S **`). | Struct holding a pointer field vs double pointer to a struct. | Forgetting `->` outranks `*` in precedence. |
| **`*p++` vs `(*p)++` vs `++*p**` | `*p++` advances `p` (returns old `*p`); `(*p)++` post-increments target value; `++*p` pre-increments target. | Advancing a pointer vs mutating the value it points to. | Writing `*p++` when trying to increment the integer stored at `*p`. |
| **Struct Val vs Ptr Passing** | Value copies entire struct (`O(size)`, caller isolated); Pointer passes address (`O(1)`, mutable). | Tiny 2-int coordinates vs large nodes/packets or in-place mutation. | Mutating a struct passed by value and expecting caller's struct to update. |
| **Little-Endian vs Big-Endian** | Little-Endian puts **LSB** at lowest address `b[0]`; Big-Endian puts **MSB** at lowest address `b[0]`. | Inspecting multi-byte `int` via `union` or `(unsigned char *)`. | Reversing bit order *inside* a byte (endianness reorders **bytes**, never bits). |
| **`typedef` vs `#define**` | `typedef` is compiler-checked type alias (scoped, atomic); `#define` is dumb preprocessor text copy. | Aliasing pointer types, structs, and function pointers. | `#define IP int*; IP a, b;` secretly making `b` a plain `int`. |
| **`enum` vs `#define` Consts** | `enum` is compiler-scoped, debugger-visible, auto-incremented `int`s; `#define` is unscoped text. | Finite state machines, switch tags, and error codes. | Trying to take `&ENUM_VAL` or mutate `ENUM_VAL++` (not addressable L-values). |

### 4. RAPID LOCK-IN (Active Recall + Spaced Repetition)

#### 60-Second Self-Test

1. **Alignment & Reordering:** Assume `char=1B, int=4B, double=8B` with natural alignment. Compute `sizeof` for `struct S1 { char a; double b; int c; char d; };` and its minimum possible `sizeof` after reordering fields.
2. **Precedence Trace:** `struct Box { int *p; };` with `arr[] = {10, 20}` and `b->p = arr`. What is the exact difference in side effects between `*b->p++` and `(*b->p)++`?
3. **Union Alignment Trap:** Assume 4-byte `int` and 1-byte `char`. What is `sizeof(union U)` for `union U { int x; char buf[9]; };`?
4. **Endianness Output:** On a Little-Endian CPU (4B `int`), `union { unsigned int i; unsigned char c[4]; } u; u.i = 0x00000102; printf("%d %d", u.c[0], u.c[1]);` — What prints?
5. **Self-Referential Bug:** Why does `typedef struct { int data; Node *next; } Node;` fail to compile, and what is the 1-word fix?
6. **Enum Auto-Numbering:** In `enum E { A, B = 5, C, D = 2, E };`, list the integer values of `A, B, C, D, E`.
7. **Macro vs Typedef Trap:** Given `#define P1 int*` and `typedef int* P2;`, what are the exact types of `b` and `d` in `P1 a, b; P2 c, d;`?

#### Spaced-Repetition Flashcards (Day 1 / 3 / 7)

* `Q: What are the two alignment rules that determine sizeof(struct) in C? | A: Each member starts at offset % align == 0, and total struct size is padded to a multiple of max(member alignments).`
* `Q: What is the alignment requirement of an array member like char buf[13] inside a struct? | A: Alignment of its element type (1 for char), NOT its total byte length (13).`
* `Q: How do you reorder struct fields to minimize padding? | A: Sort members in descending order of alignment (largest to smallest: double -> ptr -> int -> short -> char).`
* `Q: Why is s1 == s2 illegal for two C structs, while s1 = s2 is legal? | A: s1 = s2 copies raw bytes directly; == is banned because structs may contain uninitialized padding bytes with garbage.`
* `Q: How do *p->x, ++p->x, and (*p)++ parse? | A: *p->x = *(p->x); ++p->x = ++(p->x); (*p)++ = post-increment the target value pointed to by p.`
* `Q: Why must a self-referential struct store struct Node *next instead of struct Node next? | A: Embedding by value creates an infinite recursive type size (compile error); a pointer has fixed size (4B/8B).`
* `Q: What is the exact formula for sizeof(union)? | A: Smallest multiple of the largest member alignment that is greater than or equal to the largest member size.`
* `Q: How does a Little-Endian vs Big-Endian CPU store 0x12345678 across bytes b[0]..b[3]? | A: Little-Endian: 78 56 34 12 (LSB at lowest address b[0]); Big-Endian: 12 34 56 78 (MSB at b[0]).`
* `Q: What type is x in typedef int* Ptr; const Ptr x;? | A: int *const x (constant pointer to mutable int), NOT const int *x.`
* `Q: Can you apply & or ++ to an enum constant or a struct bit-field in C? | A: No — enum constants are R-values and bit-fields are sub-byte packed, so both forbid & (compile error).`

#### Answer Key

1. **`S1 = 24B`** (`a@0`, 7B pad, `b@8..15`, `c@16..19`, `d@20`, 3B tail pad). **Reordered = `16B**` (`double b; int c; char a; char d;` → `b@0..7, c@8..11, a@12, d@13`, 2B tail pad).
2. **`*b->p++`** parses as `*((b->p)++)` (returns `10`, advances `b->p` to `&arr[1]`); **`(*b->p)++`** parses as `(*(b->p))++` (returns `10`, mutates `arr[0]` to `11`, `b->p` stays on `arr[0]`).
3. **`12`** (max member size is `9B` from `buf`, max alignment is `4B` from `int`; smallest multiple of `4` at least `9` is `12`).
4. **`2 1`** (Little-Endian stores least-significant byte `0x02` at `c[0]`, next byte `0x01` at `c[1]`).
5. Alias `Node` is not in scope until after the closing `}`. Fix: add a struct tag (`typedef struct Node { int data; struct Node *next; } Node;`).
6. **`A=0, B=5, C=6, D=2, E=3`** (starts at `0`; unassigned enumerators always equal `previous + 1`).
7. **`b` is `int**` (macro expands to `int* a, b;`); **`d` is `int ***` (`typedef` binds the pointer cleanly to every variable declared).
