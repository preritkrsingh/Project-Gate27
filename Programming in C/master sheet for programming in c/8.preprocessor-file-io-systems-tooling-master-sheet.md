### 2. COMPLETE COMPRESSED MODULES (Chunked + Active Recall)

#### M1. Preprocessor Directives (`#include`, `#define`, Header Guards)

* **Cue:** How does the preprocessor rewrite C source before compilation, and what exact bugs hide inside function-like macros?
* **Intuition (Feynman):** The preprocessor is a blind text-editing robot that runs before the compiler ever sees C types, syntax, or scopes.
* **Mechanics:**
* **File Inclusion:** `#include <hdr.h>` searches system paths (`/usr/include`); `#include "hdr.h"` searches the current project directory first, then falls back to system paths.
* **Object vs Function Macros:** `#define MAX 100` does raw token replacement; `#define SQ(x) ((x) * (x))` must parenthesize **every parameter** AND the **entire expression** (use `do { ... } while (0)` for multi-statement macros).
* **Header Guards:** Wrap `.h` files in `#ifndef FOO_H` / `#define FOO_H` / `...` / `#endif` (or non-standard `#pragma once`) to prevent redefinition errors when one `.c` file includes the same header multiple times.


* **Example:** `#define SQ(x) x * x` makes `SQ(1 + 2)` expand to `1 + 2 * 1 + 2 = 5`; even parenthesized `SQ(i++)` expands to `((i++) * (i++))` → **double evaluation / UB**!
* **Trap / Edge Case:** Header guards only protect a **single** `.c` translation unit—defining a non-`static` global variable or function in a `.h` included by two `.c` files still fails at **link time** (`multiple definition`).

#### M2. File I/O (`stdio.h`): Streams, Modes & Buffering

* **Cue:** How do `FILE *` streams manage OS disk access, and how do the 3 buffering modes affect when output actually appears?
* **Intuition (Feynman):** Instead of making an expensive OS system call for every single character, `stdio.h` batches bytes in a user-space RAM bucket (`FILE *`) and flushes them in chunks.
* **Mechanics:**
* **Open/Close Lifecycle:** `FILE *fp = fopen(path, mode);` returns `NULL` on failure (always check!); modes: `"r"` (read), `"w"` (create/truncate), `"a"` (append), `"r+"` (R/W existing), add `"b"` (`"rb"`/`"wb"`) for raw binary; `fclose(fp)` flushes buffers and releases the OS file descriptor.
* **3 Buffering Modes:** **Fully buffered** (disk files — flushes when buffer fills, `fflush`, or `fclose`), **Line buffered** (`stdout` on a terminal — flushes on `'\n'`), **Unbuffered** (`stderr` — writes immediately so crash logs survive segfaults).
* **EOF Detection:** `feof(fp)` only returns non-zero **after** a read call attempts and fails past EOF; never drive a loop with `while (!feof(fp))`.


* **Example:** `printf("step 1"); *(int *)0 = 1;` prints **nothing** before crashing because `stdout` lacked `'\n'` to flush; `fprintf(stderr, "step 1");` prints immediately.
* **Trap / Edge Case:** Using `while (!feof(fp))` processes the final line/record **twice**; always test the read function's return value directly (`while (fgets(buf, sizeof(buf), fp) != NULL)`).

#### M3. Text vs Binary File I/O & Random Access (`fseek` / `ftell`)

* **Cue:** When should you use `fprintf`/`fscanf` vs `fread`/`fwrite`, and how do you jump arbitrarily inside a file?
* **Intuition (Feynman):** Text I/O translates numbers into human-readable ASCII characters, binary I/O photocopies raw RAM bytes straight to disk, and `fseek` moves the file's read/write bookmark.
* **Mechanics:**
* **Formatted Text (`fprintf`, `fscanf`):** Parses/formats ASCII (`O(chars)`); portable across CPUs, slower, and `fscanf("%s", buf)` risks buffer overflow (prefer `fgets` + `sscanf`).
* **Raw Binary (`fread`, `fwrite`):** `fread(ptr, elem_sz, count, fp)` transfers exact raw memory bytes (`struct`/arrays) and returns the **number of items** successfully read/written (not bytes!).
* **Random Access:** `fseek(fp, offset, origin)` moves cursor relative to `SEEK_SET` (start), `SEEK_CUR` (current), or `SEEK_END` (EOF); `ftell(fp)` returns current byte offset (`long`); `rewind(fp)` jumps to byte `0` and clears error flags.


* **Example:** Get binary file size: `fseek(fp, 0, SEEK_END); long bytes = ftell(fp); rewind(fp);` → then `fread(buf, 1, bytes, fp)`.
* **Trap / Edge Case:** Writing a raw `struct` via `fwrite` is **non-portable** across architectures (endianness + compiler padding differ); on `"r+"`/`"w+"` streams, switching between read and write without an intervening `fseek`/`fflush` is **UB**.

#### M4. CLI Arguments, Multi-File Projects & Makefiles

* **Cue:** How do OS arguments reach `main()`, how do `.h`/`.c` files link together, and how does `make` avoid redundant rebuilds?
* **Intuition (Feynman):** The shell hands `main` a string array of typed arguments, `.h` files publish contracts while `.c` files compile separately into `.o` bricks, and `Makefile` only recompiles bricks whose source changed.
* **Mechanics:**
* **CLI Signature (`int main(int argc, char *argv[])`):** `argc` ≥ 1 (total args); `argv[0]` = executable invocation path; `argv[1..argc-1]` = user args; `argv[argc] == NULL`. Parse integers safely with `strtol` (detects errors, unlike `atoi`).
* **Modular Compilation:** Put prototypes, `struct`/`typedef`, and `extern` declarations in `mod.h`; put definitions in `mod.c` → compile each `.c` independently (`gcc -c mod.c` → `mod.o`) → link all `.o` files into final ELF binary.
* **Makefile Rule Format:** `target: prereq1 prereq2` followed on the next line by a **literal TAB** and shell command; `make` checks file timestamps and rebuilds only if any prerequisite is newer than `target` (mark non-files like `clean` under `.PHONY`).


* **Example:** `CFLAGS = -Wall -Wextra -Werror -g` / `app: main.o net.o` / `[TAB]gcc $(CFLAGS) $^ -o $@` (`$^` = all prereqs, `$@` = target, `$<` = first prereq).
* **Trap / Edge Case:** Indenting a Makefile recipe with **spaces instead of a literal TAB** aborts immediately with `missing separator`; also forgetting to list `.h` files as prerequisites leaves stale `.o` files after editing a struct layout.

#### M5. GCC Compilation & Hardening Flags on Ubuntu

* **Cue:** What are the 4 exact stages of `gcc`, and what does each flag in `gcc -Wall -Wextra -Werror -g` enforce?
* **Intuition (Feynman):** GCC is a 4-stage factory turning C text into an executable binary, and strict compiler flags turn silent runtime bugs into loud compile-time stops.
* **Mechanics:**
* **4 GCC Stages:** Preprocess (`gcc -E` → `.i`) → Compile (`gcc -S` → `.s` asm) → Assemble (`gcc -c` → `.o` machine code) → Link (`ld` resolves `extern`/libc → ELF binary).
* **Diagnostic & Debug Flags:** `-Wall` (core warnings: uninit vars, format mismatch) + `-Wextra` (signed/unsigned compares, unused params) + `-Werror` (promote all warnings to hard errors) + `-g` (embed DWARF source/line/variable symbols into ELF).
* **Optimization vs Debugging:** Use `-O0 -g` for accurate line-by-line GDB stepping (high `-O2`/`-O3` optimizes variables into registers or inlines functions).


* **Example:** `gcc -std=c11 -Wall -Wextra -Werror -g -O0 main.c -o app` enforces strict C11 hygiene and full GDB symbol visibility.
* **Trap / Edge Case:** Linker library flags like `-lm` (math) or `-lpthread` are **order-sensitive** in GCC—always place `-lm` **after** the `.c`/`.o` files that call it (`gcc main.c -lm`), never before!

#### M6. Linux Debugging & Memory Analysis (GDB, Valgrind, ASan)

* **Cue:** How do you inspect live stack frames in GDB, and when should you pick AddressSanitizer (`-fsanitize=address`) over Valgrind?
* **Intuition (Feynman):** GDB freezes a running program like a microscope over its stack and registers, Valgrind runs your unmodified binary inside a paranoid virtual CPU, and ASan bakes tripwires directly into your compiled code.
* **Mechanics:**
* **Core GDB Workflow (`gdb ./app`):** `b main` / `b file.c:42` (breakpoint) → `r arg1` (run) → `n` (step over) / `s` (step into) / `finish` (return) → `bt` (full call stack) / `frame N` → `p var` (print) / `x/16xb addr` (inspect 16 raw hex bytes) / `watch x` (break on write).
* **Valgrind (`valgrind --leak-check=full --track-origins=yes ./app`):** Needs **no recompile** (just `-g`), ~10–30x slower → catches heap leaks, **uninitialized memory reads**, invalid heap accesses, and double frees.
* **AddressSanitizer (`gcc -g -fsanitize=address,undefined`):** Compile-time shadow-memory tripwires, only ~2x slower → catches **stack & global buffer overflows** (which Valgrind misses!), heap OOB, UAF, double free, and leaks (LSan).


* **Example:** A stack overflow `int a[4]; a[4] = 9;` passes Valgrind silently, but `-fsanitize=address` aborts immediately with exact file, line, and shadow-byte map.
* **Trap / Edge Case:** **Never** run Valgrind on an ASan-compiled binary—both hijack virtual shadow memory and crash immediately; also, ASan does **not** catch uninitialized reads (use Valgrind or `-fsanitize=memory` for that).

### 3. CONFUSION-KILLER TABLE (Interleaving)

| Concept | Core Difference | When to Use / Trigger | Common Trap |
| --- | --- | --- | --- |
| **`#define` Macro vs `static inline` Func** | Macro is untyped text copy (risks double-eval); `inline` checks types and evaluates args once. | Token pasting / compile-time constants vs small reusable logic (`max`, `sq`). | Passing `i++` or a function call into a macro that uses its argument twice. |
| **`#include <f.h>` vs `#include "f.h"**` | Angle brackets search system include paths; quotes search local project dir first, then system. | Standard/OS libraries (`stdio.h`) vs your own project headers. | Using quotes for everything or missing `-I./include` for nested project headers. |
| **`stdout` vs `stderr` Buffering** | `stdout` is line-buffered on TTY (full-buffered if piped); `stderr` is always **unbuffered**. | Normal program output vs diagnostic error/crash logs. | Debugging a segfault with `printf` lacking `'\n'` and thinking the line never ran. |
| **`fprintf`/`fscanf` vs `fread`/`fwrite**` | Text converts to/from ASCII (human-readable, portable); Binary dumps raw RAM bytes (fast, exact). | Configs/logs/CSV vs large numeric arrays, caches, or binary packets. | Reading `fwrite`'s return value as byte count instead of **element** count. |
| **GDB `next` (`n`) vs `step` (`s`)** | `next` executes an entire function call as 1 step (step over); `step` enters the callee's frame. | Skimming past `printf`/helpers vs tracing inside your own buggy function. | Hitting `s` on `printf()` and falling deep into unreadable `glibc` internals. |
| **Valgrind vs ASan (`-fsanitize=address`)** | Valgrind: no recompile, slow, catches **uninit reads**; ASan: recompile, fast, catches **stack/global OOB**. | Auditing third-party binaries or uninit bugs vs daily C/C++ dev & fuzzing. | Running Valgrind on an ASan binary (instant startup crash), or expecting Valgrind to catch stack OOB. |
| **Header Guards vs `extern**` | Guards stop duplicate inclusion in **one** `.c` file; `extern` stops duplicate allocation across **many** `.c` files. | Every `.h` file vs sharing a global variable across multiple `.c` files. | Putting `int g = 0;` inside a guarded `.h` and getting a linker `multiple definition` error. |
| **Compile Error (`-c`) vs Link Error (`ld`)** | Compile checks syntax/types in 1 `.c` file; Link resolves cross-file symbols and libraries into ELF. | Fixing missing prototypes/headers vs missing `.o` files or `-lm` order. | Seeing `undefined reference to foo` and thinking it's a missing `#include` (it's a missing `.o`/lib!). |

### 4. RAPID LOCK-IN (Active Recall + Spaced Repetition)

#### 60-Second Self-Test

1. **Macro Double-Trap:** Given `#define MUL(a, b) a * b` and `#define SQ(x) ((x) * (x))`, what does `MUL(2 + 3, 4)` evaluate to, and why is `int i = 3; int r = SQ(i++);` illegal?
2. **Linker vs Header Guard:** You wrap `config.h` in `#ifndef CONFIG_H` guards and write `int mode = 1;` inside it. Both `a.c` and `b.c` include `config.h`. Does `gcc a.c b.c` succeed? Explain why.
3. **Buffering Mystery:** A C program prints `printf("Before crash");` with no `'\n'`, then dereferences `NULL`. Nothing appears in the terminal. Why, and what are two 1-line fixes?
4. **EOF Double-Read:** Why does `while (!feof(fp)) { fscanf(fp, "%d", &x); sum += x; }` produce the wrong sum on a file containing `10 20 30`?
5. **CLI Boundaries:** You run `./scanner -p 8080 127.0.0.1` in Ubuntu. State the exact values of `argc`, `argv[0]`, `argv[2]`, and `argv[4]`.
6. **Makefile Failure:** Your `Makefile` rule fails with `Makefile:4: *** missing separator. Stop.` What exact invisible character caused this?
7. **Tool Selection:** A bug overflows a local **stack** array `char buf[8]; buf[9] = 'A';`, while another bug reads an **uninitialized** heap `int`. Between **Valgrind** and **ASan**, which tool catches which bug?

#### Spaced-Repetition Flashcards (Day 1 / 3 / 7)

* `Q: What are the two defensive syntax rules for writing function-like macros in C? | A: Parenthesize every parameter and the entire body, and wrap multi-statement macros in do { ... } while (0).`
* `Q: Why do header guards (#ifndef/#define/#endif) NOT stop multiple-definition linker errors? | A: Header guards only prevent duplicate inclusion within a single .c file, not across separate .c translation units.`
* `Q: State the default buffering modes for disk files, terminal stdout, and stderr. | A: Disk files = fully buffered; terminal stdout = line buffered; stderr = unbuffered.`
* `Q: What does fread(buf, 4, 10, fp) return on full success — 40 or 10? | A: 10 (fread/fwrite return the number of elements transferred, not total bytes).`
* `Q: What 3 origin constants does fseek(fp, offset, origin) accept? | A: SEEK_SET (start of file), SEEK_CUR (current cursor), and SEEK_END (end of file).`
* `Q: What are the guaranteed invariants for argc and argv[argc] in main()? | A: argc is at least 1 (argv[0] is program name), and argv[argc] is guaranteed to be NULL.`
* `Q: In a Makefile recipe, what do the automatic variables $@, $<, and $^ expand to? | A: $@ = target name, $< = first prerequisite, $^ = all prerequisites.`
* `Q: What do the 4 GCC flags -Wall, -Wextra, -Werror, and -g do? | A: -Wall/-Wextra enable broad warnings, -Werror turns warnings into build failures, -g embeds DWARF debug info.`
* `Q: Name the 5 essential GDB commands for setting a break, stepping over/into, viewing the stack, and dumping raw memory. | A: b (break), n (next/over), s (step/into), bt (backtrace), and x/Nxf addr (examine memory).`
* `Q: What memory bug does ASan catch that Valgrind misses, and vice versa? | A: ASan catches stack and global buffer overflows (Valgrind misses); Valgrind catches uninitialized memory reads (ASan misses).`

#### Answer Key

1. `MUL(2 + 3, 4)` expands to `2 + 3 * 4 = 14` (not `20`); `SQ(i++)` expands to `((i++) * (i++))`, modifying `i` twice without a sequence point (**UB**).
2. **Fails at link time** (`multiple definition of 'mode'`): header guards only stop double inclusion inside a single `.c`, so both `a.o` and `b.o` allocate `mode`. Put `extern int mode;` in `config.h` and `int mode = 1;` in one `.c` file.
3. `stdout` is **line-buffered** on a terminal, so the text sat in RAM when the crash killed the process. Fixes: append `\n` + `fflush(stdout);`, or write to unbuffered `stderr` via `fprintf(stderr, ...)`.
4. After reading `30`, EOF isn't flagged yet; the loop runs one extra time, `fscanf` fails (setting EOF) without changing `x`, and `sum += x` adds `30` a **second** time.
5. `argc = 4`, `argv[0] = "./scanner"`, `argv[2] = "8080"`, `argv[4] = NULL`.
6. **Spaces instead of a literal TAB** character at the start of the command recipe line.
7. **ASan** (`-fsanitize=address`) catches the **stack** overflow (Valgrind misses stack/global OOB); **Valgrind** catches the **uninitialized** heap read (ASan misses uninit reads).
