# Module 1 Master Sheet

**Track:** GATE Core · **Use:** Rapid revision

## Build pipeline

| Stage | Input → output | GCC option |
|---|---|---|
| Preprocess | `.c` → `.i` | `-E` |
| Compile | C → `.s` assembly | `-S` |
| Assemble | `.s` → `.o` object | `-c` |
| Link | object files/libraries → executable | default link step |

## Process memory model

| Area | Typical contents |
|---|---|
| Text | Program instructions |
| Initialized data | Static-storage objects with explicit initializers |
| BSS | Zero-initialized or uninitialized static-storage objects |
| Heap | Dynamic allocations |
| Stack | Function-call state and automatic objects |

This layout and the familiar heap-up/stack-down diagram are implementation
models, not C language guarantees.

## Types and `sizeof`

- `sizeof(char) == 1`; a C byte is not necessarily 8 bits.
- Exact sizes/ranges are implementation-dependent within standard minimums.
  Check `<limits.h>`, `<float.h>`, and `sizeof`.
- Plain `char` may be signed or unsigned.
- Unsigned `N`-bit arithmetic wraps modulo `2^N`; signed overflow is undefined.
- `sizeof` usually does not evaluate its operand; VLA sizes are the important
  exception.

## Conversion checklist

1. Apply integer promotions to narrow integer types.
2. Apply usual arithmetic conversions to get a common operand type.
3. Check signedness before comparing or mixing signed and unsigned values.
4. Converting to unsigned wraps modulo the destination range plus one.
5. `size_t` is unsigned: `size_t n = 0; n - 1` is a large value, not `-1`.
6. A cast requests conversion; it does not legalize signed overflow.

## Quick traps

- Never assume `int` is exactly 32 bits unless stated.
- Do not equate textbook memory diagrams with a guaranteed process layout.
- Use explicit type/range assumptions when evaluating exam questions.
